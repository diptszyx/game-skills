# Changelog

## Unreleased

- `ShellApp.StartAttempt(start)`: one gate for starting a run outside the Play button (checks hearts, offers a refill, begins the heart-costing attempt). `Play` now uses it.
- `CompactResourcePills` also shows the heart refill countdown as a clock (`29:20`, no "+1" or unit letters) and widens the lives pill.
- `ShellAppConfig.CurrentLevel`: when set (and no `PlayLabel`), the Home play button reads "Level N" (`shell.play.level`, en and vi) instead of "Play"; without it the label stays "Play".
- `ShellStyle.HideGoldPillOverGamePopups` (the gold pill no longer appears over the game HUD while a popup is open) and `ShellStyle.CompactResourcePills` (gold and hearts pills 28% / 34% wide instead of 38% each); both default off.
- `ShellApp.OpenShopOverGame()`: pauses the game and opens the Shop popup above the game screen (needs `ShellStyle.ModalTabs`); for out-of-stock skill buttons.
- Booster rewards from `ShellGameConfig.rewardBoosters` + `boosterPrice`: Quests win3/win5 grant one booster, Check-in days 3/5/7 grant boosters (day 7 all), Shop sells each booster for gold (`booster_<id>` product, title key `shell.product.booster_<id>`). Packs take the ids as an optional argument.
- Hearts countdown shows the time to the next heart as `+1 29m 13s` (`LivesService.NextHeartAtUtc`, `MainPresenter.FormatDuration`) and nothing when full; `shell.lives.full` removed. Quest titles use digits (`Win 3 rounds`).
- `ShellStyle.HideResourcePillsInGame`: gold and hearts pills fade (`TopBarView.ShowPills`, CanvasGroup) instead of deactivating, so reward flights keep a target; the gold pill reappears while a popup is open.
- Top bar gold and hearts lag a claimed reward until its fly icons land: `RewardFlyLayer.Held(icon)` holds each flight's share (`RewardPart.Amount`), `ChromePresenter` shows balance minus held.
- `IBoosterInventory` (`Count`/`Use`/`Changed`) implemented by `EconomyService`, exposed as `ShellApp.Boosters` (`Use` commits the save); `initialBoosters` in `ShellGameConfig`; booster rewards render icon + amount via `ShellAppConfig.BoosterIcons`, plain text when no icon is set.
- Hearts are spent per failed attempt, owned by the shell (`AttemptHearts`, `session.Attempt`): one heart when the lose popup shows or when an unwon attempt is left, never twice in one attempt, never on win, revive or retry. Play, Retry and Next require at least 1 heart (unlimited counts) and open the Shop when refused. Games need no heart code.
- Leaderboard rename is inline: tapping your own row turns the name into an input in place (`InlineNameEditor`, transparent, same rect as the label); Done submits, losing focus or Escape cancels, errors show on the row. The rename popup is gone; `LeaderboardPresenter` no longer takes a `PopupHost`. Optional `ILeaderboardRename` / `ILeaderboardBackend.UpdatePlayerName` back it.
- `PopupHost` lifts the top popup above the soft keyboard while a TMP input inside it is focused (`KeyboardAvoidance`, `SoftKeyboard`; Android reads the visible display frame because `TouchScreenKeyboard.area` is empty there).
- Result celebration: `IWinCelebration` is now `IResultCelebration`; `ShellAppConfig.WinCelebration` plays on the win popup with built-in confetti (an overlay above the popup), new `ShellAppConfig.LoseCelebration` plays on the lose popup without confetti. Both stop on retry, revive, next, close and presenter Dispose.
- Optional `ProgressBarView` skin (`ShellStyle` frame and fill sprites, tint) for the loading and game progress bars; flat fill is unchanged when no skin is set.
- Rewards now render as icon + amount everywhere instead of bare text: Quests and Shop row detail lines (`RowDisplay.Rewards`, replaces the `+N` detail and `ScreenText.RewardShort`) and the Win popup (`SessionPopupContent.RewardStrip`, replaces the "Gold 20" label) use one `ShellUiFactory.RewardStrip` (coin for gold, heart for hearts, plain text for boosters). `ScreenText.RewardParts(reward)` builds the pieces. New `ShellStyle.RewardIconSize` and `RewardGap`.
- Claiming a reward flies icons to the top bar counter: new `RewardFlyLayer` (created once by `ShellApp`, top bar gold and heart icons registered as targets) with pure path math in `RewardFlyCurve`. Triggered on quest claim, check-in claim and the Win popup reward (also the doubled grant). Tuned by new `ShellStyle.RewardFlyCount`, `RewardFlySeconds`, `RewardFlyStagger`, `RewardFlyIconSize`, `RewardFlyArc` (validated). `QuestsPresenter`, `CheckInPresenter` and `SessionPopupPresenter` take an optional `RewardFlyLayer`; without one nothing flies. The shell has no reduced-motion setting, so the fly always plays; gate `RewardFlyLayer.Fly` when one is added. The top bar counter still jumps to the new value immediately.
- Leaderboard rows redesigned like game-2: three columns (rank, name with ellipsis, right-aligned score with optional style icon `scoreIcon`), thin dividers, ranks 1-3 tinted by new `ShellStyle.LeaderboardGoldColor/SilverColor/BronzeColor`, the player's own row a pill (`LeaderboardOwnRowColor`, `LeaderboardOwnRowTextColor`) highlighted in place or pinned under the list with rank `-` when unranked, plus an optional one-line footer from new `ShellAppConfig.LeaderboardCaption` (key or text, `LeaderboardView` ctor arg `captionKeyOrText`). `LeaderboardEntry` gains an optional `PlayerName` and `DisplayName` (blank or id-like names show `Player` + last 4 of the id); `UnityLeaderboardBackend` now keeps the real player id and Unity's PlayerName separately. Localization: `shell.leaderboard.row`, `.mine` and `.mine.unranked` removed, `shell.leaderboard.you` added. `ListDisplay` takes optional pinned row and caption; `RowDisplay` takes optional `ScoreColumns`.
- Check-in is now a 7-day cycle and claiming is tapping today's Day cell: the separate gift claim button is gone (`DayCellView` is a `Button` with press feedback, interactive only when today; locked and collected cells are not; accessibility label is the localized Claim name on today's cell, the day label otherwise). New shared `CheckInPack.Standard(baseGold)` (`CheckInPack.Days` = 7; gold x1..x6 on days 1-6, day 7 x10 gold + 1 heart), used by `ShellAppConfig.Standard` with an optional `checkIn:` override. `DailyCheckInService` now requires `CheckInPack.Days` rewards per table; a saved slot past the cycle resets without failing boot, and old 5-day saves keep loading. Modal layout: 4 columns, days 1-4 on row one, days 5-6 and a double-width day 7 on row two (about 141 px per cell at 720 wide, measured in Colony Flow's daily reward modal as a 4-slot block plus one wide slot); the non-modal home row is one row of 7 (about 88 px at 720 wide). `CheckInView.RenderDays` takes an optional `claimLabel`.
- Leaderboard shows the player's own row even with no board entry or offline: new optional `ShellAppConfig.LeaderboardLocalBest` (and `LeaderboardPresenter` ctor arg) renders an unranked row (`shell.leaderboard.mine.unranked`, Rank 0). Unavailable errors show `shell.leaderboard.offline` instead of "Unavailable"; the empty message now invites the first win.
- Shop IAP buttons now show a localized price and no currency icon (gold-priced buttons keep icon + amount). `IPurchaseService` exposes no store price, so the label is `shell.price.iap` (now a format, en and vi `${0}`) applied to `Product.Price` read as minor units (99 -> `$0.99`); override the key per game for another currency. The row detail drops the old "Purchase" filler (`+50`). `ShellUiFactory.IconButton` with an empty icon key renders a centred text-only button.
- Check-in day cells are now a vertical stack inside each cell: day label band on top (min font 14), icon zone in the middle, reward amount centred with its coin icon in a bottom band, for every state; locked cells show the amount dimmed (`DayCellView.LockedRewardAlpha`, .75). Replaces the reward chip that sat below the cell. The state sprite (padlock, check mark, today) now draws only inside the icon band with `preserveAspect`, on a plain cell backing, so it never covers the label or the reward band.
- Every shell button now gives press feedback: `PressFeedback` squashes the button to `ShellStyle.PressScale` (default .94) and darkens its graphic by `PressDarken` (.88), then eases back with a small overshoot over `PressSeconds` (.12 s, unscaled time, no per-frame allocation). Added once in `ShellUiFactory` (`Button`, `IconButton`, new `WithPressFeedback`) plus the tab bar and settings gear; popup scrims and panel input blockers get none, and non-interactable buttons ignore presses. `ShellStyle.Validate` rejects scale or darken outside (0,1] and non-positive seconds. The shell has no reduced-motion setting and no click sound service, so neither is wired; haptics stay with `ShellApp.Haptics`.
- Add shared shop pack `ShopPack.Standard(shopGold, heartsPrice, maxHearts)`: `hearts` (gold-priced full refill) plus IAP `gold_s`, `gold_m`, `gold_l` (1x, 5x, 12x `shopGold`), sorted by price kind then price, localized in en and vi (`shell.product.<id>`). `ShellAppConfig.Standard` uses it (replacing the single `p` product) and takes an optional `shop:` catalog override; its fake purchase service now scripts 50 successes so every IAP product completes. Standard requires `shopGold > 0` unless `shop:` is given.
- New optional `ShellAppConfig.HomeStageFactory` (`Func<HomeStageContext,RectTransform>`): lets a game place animated characters or props on Home. `HomeStageBuilder` creates the stage once as the first child of Main (above the screen background, below Main content, the tab bar and every popup including tab modals), blocks no raycasts and scales the design-sized stage to Main with the same stretch the screen background uses, so layers stay registered to the picture at every aspect ratio. `ShellApp.HomeStage` exposes it; a null factory changes nothing.
- Bottom-tab screens (Check-in, Quests, Shop, Leaderboard) open as modals over Home through the shared `PopupHost`/`PopupView` (new `TabModals`), matching the original Hole It! UI: dim scrim, centred panel with the popup title zone and close X, tab bar left visible and clickable (the scrim stops above it), active tab highlighted, Home stays behind. Back/Escape closes one layer; a session popup above a tab popup closes first.
- New `ShellStyle.TabsAsModals` (default true; only effective with `EnableHomeChrome`). Set false to keep flat full-screen pages with a Back button.
- Swipe now switches the open tab modal to its neighbour (and past the first tab returns Home). Tab popups carry their own `TabSwipeHandler`; `SwipeForwarder` on list scrolls forwards drags the `ScrollRect` would swallow (also fixes swipe over lists in page mode).
- Home gear accessibility name is Settings (`popup.settings.title`) on Home and Pause only on the game screen.
- `QuestsView`, `ShopView`, `LeaderboardView`, `CheckInView` take an optional `PopupView modal` argument.
- Tab modals now fit their content: panel height = title header + rows (fixed `ShellLayout.Row` height plus `Spacing`) + bottom inset, clamped to `ShellStyle.Modal` (`WidthFraction` .894, `MinHeightFraction` .30, `MaxHeightFraction` .84 of the area above the tab bar; measured from the original Hole It! Settings 965x1325 and DailyChallenge 867x1618 panels on 1080x1920), centred, scrolling past the maximum. New `PopupView.FitModal(contentHeight)`; the panel refits when the area changes.
- Check-in modal: five equal day cells fill the panel width with equal gaps, today's cell is emphasised, and the claim button spans the width below them; no empty area. Leaderboard modal: refresh moves to the header (left of the title), own entry and own-rank row get an accent bar and bold text, empty state is one compact row-height card. Quest progress track sits in its own band under the detail line with enforced contrast (track 1.8:1 against the card, fill 3:1 against the track). `RowDisplay` gains optional `highlight`.

## 0.2.0 — 2026-11-18

- Add editor texture-import policy (ASTC 6x6 default, 4x4 detail exception, mipmaps a policy field, per-asset opt-out marker), applier, read-only audit and per-screen `SpriteAtlasBuilder` under `Editor/Textures`.
- Add shared quest pack `QuestPack.Standard(baseGold)`: five daily templates (`win1/3/5`, `play3/5`), three picked per day, localized in en and vi. Shell records `win` and `play` itself when the Win/Lose popup opens, so games no longer call `RecordEvent`. A game customizes by passing its own `DailyQuestsConfig` to `ShellAppConfig.Standard(..., quests:)` and adding `shell.quest.<id>` keys.
- Quest rows are sorted by target; the progress track sits inside the row card instead of straddling its bottom border.
- Derive popup title zones from usable panel top borders; border-less or insufficient borders retain the 104/8 layout.
- Centre one to three icon actions in an equal-size row; keep labelled actions and larger sets stacked.
- Support optional round and pill button sprites with white custom surfaces and procedural fallbacks.
- Hide lower popup views while another popup is above them, restoring them on close.
