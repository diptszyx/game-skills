## Result and integration

EconomyService takes EconomyConfig and a LivesService. GrantReward returns ModuleResult with explicit ModuleError; SpendGold, SpendBooster and atomic Spend also return ModuleResult. Claims and balances share the single version-1 `economy` section. The existing IRewardGrantor is implemented explicitly, mapping the detailed result to its required GrantOutcome. Reward hearts go through LivesService, with all economy validation completed before applying hearts and committing balances/claim.

LivesService takes LivesConfig and IClock. Refresh, SpendHeart, AddHearts, AddUnlimited, Load and Save return ModuleResult. One clock sample is used per mutation. It preserves interval remainder below maximum, discards the timer at maximum, and persists the observed time watermark to prevent backward-time regeneration or undoing prior changes. FullAtUtc is a pure query; callers refresh first. All lives data is in the single version-1 `lives` section.

NotificationPlanner takes NotificationConfig and IClock, calls ILivesNotificationSource.Refresh before querying FullAtUtc, and takes daily readiness through IDailyRewardNotificationSource. Plan returns a result containing an immutable list of immutable descriptors. Each list replaces the earlier whole plan. Same-id entries replace earlier entries in that list. There is no platform scheduler or persisted notification state.

## AMBIG — simplest choices

- The immutable IRewardGrantor contract requires an enum return, conflicting with the result-object rule. Preserve it unchanged via explicit implementation; use GrantReward for detailed result objects everywhere else.
- Constructors reject invalid dependency/configuration objects with ArgumentException, consistent with existing SaveStore configuration handling. Operational mutators return errors for bad inputs.
- Balance addition uses Reward/GrantReward; no separate unclaimed add API. An empty nonnegative reward may consume a valid claim id. Duplicate ids are checked first and always return AlreadyClaimed without changes.
- Heart rewards cap at configured maximum after checking integer overflow; excess hearts do not become over-cap inventory. Regeneration continues during unlimited windows.
- AddHearts(0) is a valid refresh; zero/negative unlimited duration and zero spending are invalid. Atomic spending accepts zero gold when spending at least one positive booster amount.
- Clock rollback freezes time at the last successful lives mutation/refresh watermark, including after save/load. Pure queries do not advance that watermark. IClock.UtcNow is expected to provide UTC values, as its contract names specify. The services are intended for serialized calls, with no concurrent-call locking.
- FullAtUtc queries the last refreshed state. It returns null when full or when the configured time-to-full exceeds representable DateTime; the latter produces no lives notification instead of overflowing.
- Missing/null module sections use configured defaults per SaveDocument behavior. Present sections require complete fields and version 1. Unsupported section versions and malformed/negative/out-of-range data reset only that module with CorruptSection; Load does not rewrite the document automatically. The save root version remains SaveStore's concern.
- Quiet hours are start-inclusive/end-exclusive UTC; equal start/end disables quiet hours. Quiet notifications move forward to the next end boundary. Daily readiness in the past schedules at now; null means no daily reminder.
- Planner owns no scheduler or persistent plan: the returned list is the entire replacement plan. Configured id collisions use the later daily descriptor. An unrepresentable quiet-hour shift is rejected, returning an empty plan and an error.
