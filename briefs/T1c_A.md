1. Economy: balances gold (long), hearts delegated to Lives, boosters (string id -> int). Implements IRewardGrantor with a ClaimLedger of claim ids persisted in the save (claim id seen before => AlreadyClaimed, nothing added). Spend(gold|booster): rejected if insufficient, negative, zero-invalid, or overflow; atomic multi-item transaction: if any item fails, state unchanged. Required behaviors: negative amount rejected; overflow on add rejected not wrapped; failed transaction leaves state unchanged; duplicate claim id grants once; state survives save+load round trip; corrupt section falls back to defaults with error code.
2. Lives: max hearts, one heart per regen interval, regen computed lazily from timestamp of last change via IClock; unlimited-lives time windows are ADDITIVE (second window extends the first); hearts below max regen, at max no timer. Required: partial interval carries over; clock going backward gains and loses nothing; long offline gives at most max; unlimited window active/expired boundaries; spend a heart when unlimited does not consume; refill-time query (when will hearts be full) for Notifications; save round trip.
3. Notifications: pure planner producing a list of scheduled notification descriptors (id, fireAtUtc, textKey) from Lives and daily-reward-ready inputs through small interfaces you define in Notifications/. Lives must be refilled/refreshed to now BEFORE computing the lives-full time. Required: lives-full time computed after refill; no notification for already-full lives; replaces earlier plan with same id (no duplicates); respects a quiet-hours window in UTC config.
