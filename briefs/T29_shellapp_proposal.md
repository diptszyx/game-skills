# T29 PROPOSAL (for read-only critique): ShellApp = the missing composition root of the shell package
Problem measured: package com.indiegame.shell has NO runtime caller of ScreenHost.Initialize / new MainPresenter / CheckInPresenter / QuestsPresenter / ShopPresenter / LeaderboardPresenter / SessionPopupPresenter / PopupHost. Only game-2-v2/Assets/Scripts/PilotApp.cs (214 lines, outside this repo) assembles them (lines 56-101 boot, 147-170 lazy service screens, 22 serviceScreens cache, BackButton, Loading overlay, language toggle). So each new game would copy ~150 lines. Goal of the whole tool: given a game idea the user only thinks about gameplay. T28e (home screen + ChromePresenter) is blocked on this.
Proposal:
1. New Runtime/Unity/ShellApp.cs (MonoBehaviour) + ShellAppConfig (plain data class, built by the game): ShellStyle, language tables (language -> TextAsset json), save file name, SessionConfig set (LivesConfig, EconomyConfig, DailyCheckInConfig, DailyQuestsConfig, SettingsConfig, RemoteConfigRules, SessionPopupConfig), IGameSessionActions game, optional services (IRewardedAdService, ShopService/catalog + purchase service, ILeaderboardService + board id), and a game-screen registry.
2. ShellApp.Boot(config) creates Canvas+Scaler(720x1600, match 0)+GraphicRaycaster, EventSystem if absent, ScreenHost, safe popup root + PopupHost, ShellSession (LoadAll, shows localized error if load fails), LocalizationService, SessionPopupPresenter, MainView+MainPresenter, lazy cached CheckIn/Quests/Shop/Leaderboard screens, loading overlay with tip, a shell-owned Back action (Android back + a back control on non-home screens; today PilotApp adds its own "Pilot Back"), and when style.EnableHomeChrome the T28e ChromePresenter. Exposes Session, Text, Screens, Popups, Navigate(ShellScreen), ShowMain(), ShowGame(), Ready, Commit().
3. The game plugs ONLY: its gameplay screen via `RegisterGameScreen(Func<ShellUiFactory,Transform,RectTransform> build)` (shell shows/hides it on Play/Leave), the IGameSessionActions implementation, and config data. Pilot debug extras (save button, language toggle footer, "first3" label) stay game-side or are deleted; language switching becomes a shell settings concern later (not in this step).
4. Migration proof: PilotApp is reduced to config + board + actions on top of ShellApp (separate step after the package part is green; PilotApp is outside this repo, edits are uncommitted there).
5. Tests: EditMode building blocks unchanged; new PlayMode boot test using a temp save path (no auto-boot), real EventSystem pointer taps for nav + back; boot fails loudly with a named missing role/table instead of silently.
